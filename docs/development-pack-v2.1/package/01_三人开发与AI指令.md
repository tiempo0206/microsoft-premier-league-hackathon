# 三人开发与AI指令

开发时以starter-overlay/matchmind为工作目录，每人只读取自己的角色任务卡。共同协议保持2.0.0。先完成国内环境设置，不等待云资源。

# A 前端体验负责人交给 AI 的任务卡

你的角色是A，只改frontend/、tests/frontend/和docs/handoff/frontend.md。职责是把数据和可信解释呈现为英文网页，完成演示交互和视频素材。禁止改后端、AI、契约和固定数据。

环境先读docs/01_cn_setup.md，模型与国际部署读docs/03_resources.md。文中的python命令必须使用本项目.venv解释器。共同Python检查在matchmind根目录执行，pnpm命令在frontend目录执行，不要混用工作目录。国内开发优先项目镜像、本地静态资源和随包数据；不要求先有Azure或Docker。

## 工作块 A1

读取共同文件，运行 `python -m tools.mock_api`。创建React/Vite入口和基本页面，使用现有frontend/package.json及contracts/types.ts，不再运行会覆盖配置的脚手架。先实现GET matches、POST replays、接收snapshot。做出合成标签、25:00时钟、比分、射门、传球和加载/错误状态。验收：页面能选择唯一片段并显示Mock返回的状态。

## 工作块 A2

实现play、pause、reset和1/2/5/10倍速，按钮调用冻结接口。SSE使用EventSource并逐类监听；snapshot完整替换，match_state更新统计，match_event更新事件列表，insight按ID去重，agent_status显示真实阶段。任何时候不能通过match_event再累计统计。reset后按run_id丢弃旧消息。先用Mock的完整快照完成流程，不等待生产细分事件。

## 工作块 A3

做Insight卡、Casual/Analyst切换和证据展开。点击证据高亮对应事件与事件点，显示时间、类型和指标，P0不做seek或无球轨迹。Rule fallback、Precomputed、Live model、Evidence checked有明确文字。模式切换读同一Insight的两段文本，不再调用模型。

## 工作块 A4

接B真实API时只改Vite代理目标或部署配置，不能改页面字段。执行播放、暂停、重置、断线重连、模型失败、旧run结果丢弃和两模式一致性。发现接口缺项先提交契约问题，禁止写临时字段兼容多种拼法。

## 工作块 A5

桌面1280×720和手机390像素宽检查，按钮可键盘操作，状态有语义文字。优化证据高亮和阅读体验，先保证一种主题和一个页面，不加大图表库、登录页或聊天机器人侧栏。检查前端不含任何API Key；不加载Google字体、远程脚本CDN或在线占位图，图标和资源在本地构建。

## 工作块 A6

与C按docs/05_acceptance.md排练110秒英文演示；把实际画面交给用户确认。视频只展示已实现能力，故障注入有标签。更新handoff。

## 本角色检查

本包包含pnpm-lock.yaml，统一运行pnpm install --frozen-lockfile；依赖修改由A说明原因并重新提交锁文件，其他角色不改此锁。至少运行pnpm run typecheck、pnpm run build、角色测试与共同Python契约测试。前端尚未建立入口时build不通过属于待开发状态，不能声称启动包已含完整UI。

给AI的第一次消息：

> 我是MatchMind角色A。读取roles/A_FRONTEND.md和共同规则。只实施A1，使用tools.mock_api提供的接口；不要等待后端或模型，不改contracts。先列修改文件，再写代码并运行检查。未完成的部分明确列出。


# B 数据后端负责人交给 AI 的任务卡

你的角色是B，只改backend/、data/generator/、data/extra/、tests/backend/、deploy/和docs/handoff/backend.md。数据样例已经提供，你不负责模型开户、Prompt、前端页面或共享契约。使用ai.service.analyze桩独立完成后端。

环境先读docs/01_cn_setup.md，模型与国际部署读docs/03_resources.md。文中的python命令必须使用本项目.venv解释器。共同Python检查在matchmind根目录执行，pnpm命令在frontend目录执行，不要混用工作目录。国内开发优先项目镜像、本地静态资源和随包数据；不要求先有Azure或Docker。

## 工作块 B1

安装requirements-contracts.txt和backend/requirements.txt。实现backend.app:app及health、matches、match详情、events、stats。启动命令固定 `python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000`。读取随包JSON/JSONL；实现统计纯函数，按固定样例验收：1650时HOME射门2、AWAY0、比分0:0、持球35:115；1800时比分1:0，不能把shot(goal)和goal加两次。禁止先写完整足球生成器。

## 工作块 B2

实现Replay创建、查询和control，时钟由服务端维护。每个会话独立，reset增加run_id，play/pause/set_speed按契约执行。至少写两会话隔离、暂停、重置测试。模型先不接，保证数据闭环。

## 工作块 B3

接sse-starlette，用完整snapshot起流，再按冻结六种事件名称推送；每个订阅者独立队列、心跳、断线回收。支持快照重连，不承诺日志补发。前端根据状态显示，后端不得等待模型才发统计。

## 工作块 B4

实现高位夺回检测和窗口提取，调用 `await ai.service.analyze(request)` 但放在有界后台任务中。同一replay+run+window+type只调一次；只发布check_result和can_publish都通过的结果。C尚未完成真实模型时桩返回fallback是正确行为；不要自己写第二套模型调用。把窗口所需事件和指标完整打包，不让C反查你的内部数据库。

## 工作块 B5

与A联调；落实会话容量、空闲回收、分析次数限制和请求体上限。用当前epoch拦截reset前的旧结果。托管frontend/dist，/api不被SPA回退路由吞掉；生产同域、单worker。Docker启动脚本、健康检查和SSE代理配置放deploy/。与C确认公网宿主，部署账号开通由本人操作。

## 工作块 B6

公网匿名验收并记录版本、URL、费用责任和保活到期日。容器重启会丢失内存回放，前端应明确重新开始。不要在这一轮加多副本、Redis或数据库。公网发布需人类授权，不能把本地Mock暴露为正式产品。

## 本角色检查

共同契约测试、tests/backend/和一次与A的真实端到端。覆盖比分不双计、窗口边界、坏ID、pause/reset、两个订阅者不抢消息、重连快照、旧run结果、模型失败统计仍更新。参考tools/reference.py来写期望，不直接把Mock服务搬成生产后端。

给AI的第一次消息：

> 我是MatchMind角色B。先读roles/B_BACKEND.md和共同契约。只实施B1，先使用现成fixture，按规定路径实现FastAPI与统计。不做模型和前端，不改contracts或固定fixture。完成后运行检查并交付可重复启动命令。


# C AI核验与集成负责人交给 AI 的任务卡

你的角色是C。日常功能只改ai/、evaluation/、tests/ai/和docs/handoff/ai.md；另承担共享基线维护和每日合并。共享契约变更必须单独审查，不能利用集成人身份随意改A/B代码。P0不启用DSPy优化；先完成可解释闭环和小型固定评测。

环境先读docs/01_cn_setup.md，模型与国际部署读docs/03_resources.md。文中的python命令必须使用本项目.venv解释器。共同Python检查在matchmind根目录执行，pnpm命令在frontend目录执行，不要混用工作目录。国内开发优先项目镜像、本地静态资源和随包数据；不要求先有Azure或Docker。

## 工作块 C1

把共同基线导入仓库，记录BASELINE_SHA并确认三人角色。运行生成类型、冻结摘要与共同测试，向A/B发同一commit。使用contracts/examples/analysis_request.json独立运行ai.service.analyze，核对fallback标签。与成员确认每天一次集成时间。不要等待模型账号才发基线。

## 工作块 C2

按docs/03_resources.md由本人开通一个国内模型API。先配置检查，再在用户允许费用后显式运行一次 --live 探针；只记录成功标志、模型名、usage和延迟，不记录Key。如果平台注册/实名/支付阻塞，继续离线审核模块，同时尝试文档中的官方备用供应商。不要向AI聊天发送密钥。

## 工作块 C3

实现独立的结构化分析、双模式叙事、审核和程序校验，保持async analyze(dict)->dict边界。先用模型mock单测验证分支，再用少量实际合成窗口实测。所有事实来自输入，审计提出correction request后最多纠正一次。总deadline与并发生效；超时或错误返回诚实的规则fallback，不无限重试。

## 工作块 C4

用Microsoft Agent Framework接管已验证流程，选择OpenAIChatCompletionClient接国内Chat Completions端点。先单Agent导入与无密钥实例化，再真实单次调用，再串联analyst/narrator/auditor。角色有不同任务和输入，不复制同一个Prompt改名字。Trace来自实际执行。通过注入“对方体能下降”等证据不足推断展示审核能力；故障注入标为测试，不伪装为自然输出。

## 工作块 C5

做12个起步评测，单Agent和多Agent共享输入、模型和确定性校验器。记录错误、纠正成功、耗时与调用数，不保证多Agent一定更快或更便宜。B用异步任务调用时不改签名；两个观众文本在一次结果中产出，由A本地切换。

## 工作块 C6

每日合并小PR并跑共同检查和已有角色测试；与A/B验收reset旧任务、模式、模型故障、公网访问。填实际技术栈、模型路由和未实现项，与提交代表完成材料。源码公开和正式提交由具有权限的成员在用户授权下执行。

## 本角色检查

非JSON、空响应、错误ID、越界时间、错误数字、证据不足推断、超时、一次纠正上限、fallback标签、返回身份原样保留。测试必须mock网络，不能因开发机恰好有密钥就调用付费API。共享初始契约测试中mock模式语义需继续成立。若通用fallback遇到错误输入，优先reject而不是用错数字生成解释。

给AI的第一次消息：

> 我是MatchMind角色C。先读roles/C_AI.md、AI_RULES.md和docs/02_contract.md。只完成C1并验证无密钥AI边界；不要开始部署、付费调用或改前后端。先把共同基线准备好，让A/B可以立即开工，再报告资源开通所需的人类操作。


# 不同 AI 的并行与合并规则

## 共同基线先行

C只新增matchmind子目录，不改仓库现有协作规范。团队确认TEAM_ROLES后，先提交共同基线，记录commit SHA。A/B/C都从这一SHA开分支；禁止各自让AI重新脚手架整个仓库。分支建议codex/frontend-xxx、codex/backend-xxx、codex/ai-xxx，具体仍服从仓库原有规则。

## 文件归属

| 文件范围 | Owner | 其他人怎样依赖 |
| frontend/、tests/frontend/ | A | 只通过HTTP与共享类型对接 |
| backend/、data/generator/、data/extra/、tests/backend/、deploy/ | B | 复用固定fixtures；只调用ai.service.analyze |
| ai/、evaluation/、tests/ai/ | C | 只接收AnalysisRequest并返回AnalysisResult |
| contracts/、data/fixtures/、tools/、共享测试、根配置 | C作为集成人 | 日常冻结，变更需受影响成员审查 |
| docs/handoff/frontend.md / backend.md / ai.md | 各自对应角色 | 写自己的进度，不互相改 |

A修改前端自己的依赖文件，B修改backend/requirements.txt，C修改ai/requirements.txt。新增依赖前先与共同约束比较，不能让各自AI独立升级Python/Node主版本。C负责整合跨模块依赖锁；本包提供精确顶层版本，不把它冒称为完整跨平台传递依赖锁。

## 每个工作块

1. 拉取共同分支最新状态，先查看git status，保留已有改动；不要用reset --hard或强推。
2. 告诉AI本次角色、任务编号、允许目录和契约版本。只做一个小块。
3. 运行共同契约测试和角色测试。用 `python tools/check_scope.py --role A --base HEAD` 检查当前未提交变更；B/C换角色。若检查已提交分支与基线的差异，--base填BASELINE_SHA。
4. 审查完整diff、更新自己的handoff，再提交小变更。工具只能报告路径，不能代替人的代码审查。
5. C每天固定一次集成。先合并不会破坏消费者的契约兼容改动，再合并模块。发生冲突由原Owner解决本模块，C决定共享边界。

## PR 必须写清楚

写任务、变更文件、契约版本、实际测试命令和结果、演示方式、是否有模型真实调用以及未完成项。至少另一名成员审查。不得仅写“代码已完成，请合并”。主分支先跑共同测试，再跑已实现的前后端检查；功能从Mock换真实API时必须做一次端到端联调。

提供 integration-snippets/ci.yml 供C在看过仓库现有CI后放入根.github/workflows。不要直接替换现有CI。CI需要新增前端构建和正式后端测试，不能把仅通过契约测试等同于产品验收。

## 契约变更

提出原字段、新字段、消费者影响、兼容策略、样例和测试。受影响者确认后由C改真源、生成类型、升级VERSION、更新冻结摘要，再一次合并。不能手改types.ts，不能只更新哈希消除失败，不允许在冻结日前一天加第二套API。

目前不能独立保证GitHub主分支保护已启用。拥有仓库管理权限的人按团队决定配置required checks和review；这需要真实管理权限，不是文档写一句就已经生效。
