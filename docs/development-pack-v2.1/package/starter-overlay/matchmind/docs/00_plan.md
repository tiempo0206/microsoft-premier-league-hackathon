# MatchMind AI 三人执行方案

## 最终实现目标

交付一个无需评委登录的英文网页。用户播放一段标为 SYNTHETIC 的五分钟赛事片段，看到比分、射门、传球和持球时间更新；在高位夺回关键窗口触发 AI 分析，得到普通球迷与分析师两种解释，点击解释可高亮支撑事件；错误引用被拦截；模型失效时仍能回放并显示清楚标注的规则回退。

这版先把一个场景做成完整产品。P0 只有高位夺回机会；快速反击和持续控球保留在协议枚举中，列为 P1，不要求首轮实现。P1 再做赛后小结、更多片段和更丰富的个性化。实时视频识别、无球跟踪、语音、账户系统、向量库、模型训练和完整 90 分钟生成器均为 P2。

## 国内开发和国际发布

开发使用内置原创数据、本机Mock、清华PyPI镜像、项目npmmirror和国内模型API；生产可以在Render或Azure等国际站点运行单常驻容器。开发不依赖海外模型账号或Docker Hub拉取；国际构建与发布由B集中处理，C验证云端到国内模型的真实连通性。具体命令见docs/01_cn_setup.md。

## 三人分工

| 角色 | 唯一主责任 | 可独立开工的输入 | 首次交付 |
| A 前端体验 | React 页面、回放交互、双模式、证据展示、演示视频 | Mock API 和生成类型 | 使用 Mock 完整走一遍 |
| B 数据后端 | 固定样例读取、统计、触发、回放会话、SSE、部署 | 固定 fixture 和 AI 桩 | 无密钥的真实后端闭环 |
| C AI核验与集成 | 模型开户、Agent、审核、对照评测、共享契约、合并 | AnalysisRequest 固定输入 | 离线审核与可替换 analyze 函数 |

不把三人的时间全部排满。每人按六个 60—90 分钟工作块推进，属于排期假设而非工时承诺；前两个工作块优先跑通离线闭环。角色卡给出了逐块交付要求，时间不足时保留 P0，停止添加 P1。

## 三个可交付阶段

阶段一是工程闭环：一份合成样例、真实后端、真实 UI、规则回退、证据和重置。此阶段用于消除接口问题，不能对外宣称真实多 Agent 已完成。

阶段二是有效 AI：使用国内模型 API，实现实际分析、叙事和审核；有代码校验及最多一次纠正；记录实际模型、耗时、调用次数和失败状态。阶段二才达到本项目的 AI 参赛底线。

阶段三是冲奖增强：由 Microsoft Agent Framework 执行已验证的协作链，保留可观察交接、纠正案例和与公平基线的对照结果。框架接入若不稳定，保住阶段二并如实说明实现方式；不得把未使用的微软产品写入提交材料。优先争取 Best Multi-Agent System；Foundry 专项只有真实使用并有证据时再考虑。

## 产品的记忆点

主演示让评委亲眼看到一条解释的证据，以及一条不受证据支持的推断被审核修正。仅列事件 ID 不足以让普通球迷理解，A 应把关联事件高亮在时间线和简图上。界面标签使用 Evidence checked，避免把推断包装成已证明的战术因果。
