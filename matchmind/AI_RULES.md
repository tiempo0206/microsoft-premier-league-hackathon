# 所有开发 AI 共用的规则

1. 先确认人类分配的角色，只实现这一角色的任务。先读共同契约与现有代码，不能凭旧聊天或自己的习惯改字段。保留用户已有、其他角色及未提交的改动。
2. 文件白名单见角色卡。不得顺手重写其他角色模块、生成第二套后端、搬动目录或统一格式整个仓库。新增依赖要说明用途和版本；共享依赖冲突交 C 处理。
3. contracts/contract.schema.json 是协议真源；types.ts 是生成文件。所有时间为比赛逻辑秒；耗时为真实毫秒。窗口事件边界统一 start_sec <= timestamp_sec <= end_sec；持球时长按时间区间积分。
4. 只使用 tools/reference.py 作为测试和 Mock 的参考，不把 Mock 服务作为正式后端，不把静态 analysis_result.json 当作真实模型输出。正式产品按实时事件和实际模型生成结果。
5. A 不能等待 B：先对 Mock 接口做产品。B 不能等待 C：先接 async analyze(dict)->dict 桩。C 不能等待 B：先用固定输入完成校验、失败回退和真实模型探针。
6. 前端不得持有模型密钥。真实 .env 不入库、不贴群聊，不写进日志、视频或 AI 提示词。只向模型发送本任务所需的合成事件和指标。已有账号认证由本人操作。
7. 不在自动测试中做真实付费调用；只有获得用户授权、配置本地密钥并显式选择 live 时才发起模型请求。Mock、规则回退、预计算和真实模型必须有明确状态。
8. 每次只做一个角色卡里的工作块，先列出将改的文件与验收命令，再实现、测试、看完整 diff。完成后更新自己的 handoff 文件：版本、文件、接口、测试、已知限制、下一块任务。
9. 不无限重试、不通过放宽校验掩盖错误、不删除失败测试。模型最多一次纠正请求；整体 deadline 生效后返回清晰回退。R2 重置后的旧任务即使完成也不能发布。
10. 提交、推送、PR、合并、开通付费资源、发布公网服务均遵守用户与工具权限；文档不能代替用户授权。C 做最终合并，其他人提交小 PR 或可审查提交。

## 每次交付给团队的固定格式

- 角色、分支、基线 SHA、契约版本。
- 本次完成的用户行为和修改文件。
- 执行的测试命令、结果及失败原因。
- Mock / fallback / live 的实际状态。
- 是否需要共享契约变更；没有就写没有。
- 仍未完成的内容；禁止把计划写成已经实现。

## 中国开发与国际部署约束

依赖镜像使用docs/01_cn_setup.md，包版本和契约不变。镜像缺包切官方源，不私自降级或重建锁文件。前端不用海外字体、脚本CDN、远程比赛样本；生产可国际部署，但仍同源API、单进程容器、后端保存模型密钥。云上再次验证国内API，不能从开发机成功推断云上成功。
