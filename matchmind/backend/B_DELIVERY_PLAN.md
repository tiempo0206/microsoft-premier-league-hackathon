## 系统回测，而非模型训练

阈值来自现有契约，不从合成数据调参。回测只验证 B 的读取、统计、事件关联和触发正确性；不训练模型、不报告真实足球预测准确率，也不进入 C 的 evaluation/ 目录。

1. 固定基准：保留现有30条原始/校正版数据及独立审计结果，不覆盖共享源文件。
2. 正常场景：有限的足球事件模板，覆盖正例、射门超过15秒、低位夺回、同次夺回多次射门、阈值相等/略低、空观察窗、窗口外未来射门。
3. 变化维度：固定开发种子与独立留出种子、HOME/AWAY、左右进攻方向、球员、时间和坐标；同一配置可重复生成同一份数据。
4. 独立预期：生成器不导入 B 统计实现；时间占用用逐秒参考法，规则预期由模板规范给定，避免把待测函数的结果当标准答案。
5. 异常集单列：时间/坐标越界、错比赛、乱序、冲突重复、球员或持球 ID 跨队、传球终点缺失、进球球员不一致。
6. 回测与验收导出覆盖表、数据 SHA-256、失败案例和实际检查数；开发与留出结果分别报告。留出模板仍与开发模板相关，不冒充真实独立赛事或模型泛化评估。
7. 修改 B 统计/数据代码后运行同一完整验收；失败先定位，不改契约、预期值或阈值掩盖问题。

## 检查与交付顺序

统一命令：`python -m deploy.verify_backend`（使用本项目 .venv，在 matchmind 目录）。顺序固定为数据准备/审计 → 分析导出 → 合成回测 → 后端/共同测试 → 自有临时 HTTP/SSE 服务 → 回收进程和端口 → 导出验收记录。

之后只推进尚未完成的关卡：Linux 镜像验证 → Render 公网构建与回归 → 按 A/C 契约联合验收 → 人类安排 PR/合并和最终发布。没有账号时先完成全部离线部分，不要求人类为继续写 B 代码先注册云产品。

### 已固定的回测产物

默认回测包含512个正常场景和72个异常场景，开发种子1–8、留出种子1001–1008。正常与异常数据分别写入 `backtest/normal-scenarios.jsonl`、`backtest/invalid-cases.jsonl`；`backtest.json` 和 `backtest.md` 记录各组结果、输入哈希和覆盖数，失败原样导出到 `failing-cases.jsonl`。

这批数据只用于 B 离线正确性回归，不加入默认比赛目录，不替换30条演示数据，也不进入容器构建上下文。回测已纳入统一验收命令。单独复跑可用 `python -m backend.backtest --output-dir .artifacts/backend-backtest`。生成器与预期计算不依赖待测统计代码；测试会注入关联射门丢失和进球双计错误，要求回测能明确失败。
