# 可直接发给A或C的接手提示词

以下任务在你的人类授权和已认领角色范围内执行；C统筹#15的数据方案，A负责前端消费与来源呈现。

> 请从main读取matchmind/data/extra/real-history-wyscout/README.md、manifest.json、ATTRIBUTION.md及当前TEAM_ROLES.json。这里已经包含真实历史比赛对象、1,768条全场原始事件和96条5分钟原始样本；完整原始zip在同仓库data-wyscout-2017-18-v1数据Release，无需再让B找数据。
>
> 先在matchmind运行python -m data.generator.real_history --verify，并读取samples中的原始字段。样本是2017-08-11 Arsenal–Leicester City历史记录，不是当前赛季直播；全场比分4–3不能当作25:00片段起始比分。
>
> 优先选择“真实数据对照/校准合成数据”路线，保持当前合成演示和线上部署正常。比较前先对齐事件类型、窗口和单位，记录统计及分布的计算方法；数据来源及派生量明确标注，不把小样本写成英超准确率。
>
> 若你是C：作为#15的接收/统筹人，确定映射与范围，协调A的展示字段。现有协议2.0.0固定synthetic=true，真实历史模式需版本化来源表示，不能将真实事件伪装成合成。原数据没有显式possession_id/recovery；不得补造夺回、压力或3/2触发结果。对当前规则不能诚实算出的指标明确说明。只有具备人类部署授权并完成验收时才发布新模式；本交接包不要求立即切换线上。
>
> 若你是A：可立即校验、读取提供的真实样本，准备来源/比赛日期/历史回放标签及界面消费方案；通过#15与C确认实际接入字段和校准展示。保持自己的角色边界，不重写B数据处理或C模型逻辑，也不把虚构队伍改名成真实俱乐部。已上线版本不因收到本包自动改动。
>
> 最终交付给团队：采用的是校准还是独立历史模式、数据版本和校验结果、映射/统计说明、来源署名、验收证据及是否有线上变更。普通数据接手不再等待B本人提供账号、下载或手工配置。保留当前合成数据作为可工作的参赛主链路，并遵循官方规则§4.7。
