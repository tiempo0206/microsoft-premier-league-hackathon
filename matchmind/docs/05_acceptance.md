# 验收与演示目标

## P0 完成标准

1. 从新浏览器打开公网网页，无付费或私人邀请阻断，清楚标注合成赛事片段。
2. 一场片段能够播放、暂停、倍速、重置；比分、传球、射门与固定样例一致。
3. 1500—1650窗口产生高位夺回分析：3次高位夺回，2次关联射门。用户可检查事件序列。
4. Casual与Analyst基于同一证据和数值；切换不产生额外模型请求。
5. 真实模型至少完成一次实际解释与审核流程，保留经过脱敏的模型和耗时证据。使用微软框架时有真实执行记录。
6. 注入不存在ID、错误数值、越界事件、旧run结果均被拒绝；重置和第二会话不会接收旧结果。
7. 模型故障仍能回放，显示Rule fallback；预计算必须另标Precomputed。没有真实模型时不能标Live AI。
8. README、一键启动步骤、公开仓库、可测试URL、英文提交材料和少于120秒的视频均完成。

## 必测场景

- 正常闭环与两种观众模式。
- 当前任务未完成时reset，等任务返回后仍为空的新回放。
- pause停止事件推进，但允许当前窗口AI完成。
- 两会话同时播放，不相互修改速度和结果。
- SSE断线重连，新快照恢复当前状态，不重复累计比分。
- 模型401、429、超时、非JSON和审核拒绝，均有界失败。
- 匿名访问公网；外部API密钥在浏览器源码、响应和日志中不可见。

## 对照评测

时间少时先做12个窗口：4个正例、4个负例、4个篡改或证据不足例，再扩到30个。用固定seed但未用于调阈值的额外样例作为保留测试，不能把演示同一片段反复跑当作泛化证据。

比较单Agent与多Agent时使用相同模型、证据和确定性校验器，记录每种方式调用数、tokens和总耗时。比较无依据主张、数值/引用错误、任务成功率、修正成功率和延迟。三次成功只报告3/3，不能据此宣称长期95%可靠性。不伪造领先数值，也不因结果不好就换测试集。

## 110 秒视频

0—10秒说明一个问题；10—30秒展示回放和关键窗口；30—65秒展示真实分析、审核与证据高亮；65—80秒切换观众模式；80—95秒展示一次明确标注的错误注入及修正；95—110秒给出实际技术栈、测试结果和入口。故障注入应标为演示测试，不能冒充模型自然出现的错误。模型长延迟时先手动暂停当前片段，保持解释和证据对齐。
